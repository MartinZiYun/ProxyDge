## English

### ProxyDge v0.1.0 — Initial release

*2026-08-21*

First release of ProxyDge, a PROXY Protocol normalizing gateway. It listens on a single TCP port, accepts upstream connections (direct / PROXY Protocol v1 / v2), normalizes them all to PROXY Protocol v2, and forwards to a single configurable downstream. The downstream therefore always receives a uniform v2 header — the upstream protocol variant differences are absorbed by this service.

#### Highlights

- **Protocol normalization**: direct, PROXY v1, PROXY v2 → uniform PROXY v2 output
- **Library isolation**: the `go-proxyproto` library is confined behind an adapter subpackage; business code never imports it directly, so swapping the library only touches that one subpackage
- **Unified config layer**: CLI flags / `PROXYDGE_*` env vars / YAML config file resolved through one Source with centralized validation
- **CLI subcommands**: `start` / `init` / `version` / `help` (bare run prints help)
- **Release pipeline**: version package + GitHub Actions + GoReleaser, producing Linux & Windows binaries for amd64 + arm64

#### Features

- **Gateway core** (`internal/gateway`): accept loop, normalization, and PROXY header detection with a configurable timeout; unified `*slog.Logger` leveled logging
- **Protocol abstraction** (`internal/proxyproto`): protocol types and interfaces; the concrete adapter in `goproxyproto/` implements them via `go-proxyproto`
- **Transport abstraction** (`internal/transport`): `Conn` / `Listener` / `Dialer` interfaces with a TCP adapter
- **Composition root** (`main.go`): wires CLI, adapters, and signal-based graceful shutdown
- **Config & logging**: dual-sink logging (console + file) with `text` / `json` formats; `-init` generates a sample config; startup banner prints the version, the loaded config file, and the source of every field

#### Fixes & Refactors

- `refactor(config)`: abstract the config layer into a unified CLI/ENV/YAML Source with centralized validation
- `fix(goreleaser)`: drop `-trimpath` from ldflags and resolve the `archives` deprecation
- `fix(ci)`: use block-style `workflow_call` outputs to avoid shell brace conflicts
- `fix(push)`: grant `contents:write` so the reusable CI can push the `build-counter` branch

#### Release Infrastructure

- Version system + GitHub Actions: a `version` package with ldflags-injected build info, a global Build Number, and push/release workflows driven by GoReleaser

#### Downloads

Linux & Windows, amd64 & arm64 — see the [Releases](https://github.com/MartinZiYun/ProxyDge/releases) page.

**Full Changelog**: https://github.com/MartinZiYun/ProxyDge/commits/v0.1.0

## 简体中文

### ProxyDge v0.1.0 — 首个发布

*2026-08-21*

ProxyDge 的首个发布 —— PROXY Protocol 归一化网关。监听单个 TCP 端口，接收上游连接（直连 / PROXY Protocol v1 / v2），全部归一化为 PROXY Protocol v2，转发给单一可配置的下游。下游因此永远只收到统一的 v2 头，上游协议形态的差异被本服务吸收。

#### 亮点

- **协议归一化**：直连、PROXY v1、PROXY v2 → 统一输出 PROXY v2
- **库隔离**：`go-proxyproto` 库被挡在适配器子包后面，业务代码不直接 import，换库只改该子包
- **统一配置层**：CLI flag / `PROXYDGE_*` 环境变量 / YAML 配置文件通过统一 Source 解析，集中校验
- **CLI 子命令**：`start` / `init` / `version` / `help`（裸跑显示 help）
- **发布流水线**：version 包 + GitHub Actions + GoReleaser，产出 Linux 与 Windows 的 amd64 + arm64 二进制

#### 功能

- **网关核心**（`internal/gateway`）：监听循环、归一化、带可配置超时的 PROXY 头探测；统一 `*slog.Logger` 分级日志
- **协议抽象**（`internal/proxyproto`）：协议类型与接口；具体适配器在 `goproxyproto/` 用 `go-proxyproto` 实现
- **传输抽象**（`internal/transport`）：`Conn` / `Listener` / `Dialer` 接口 + TCP 适配器
- **组合根**（`main.go`）：装配 CLI、适配器与基于信号的优雅关闭
- **配置与日志**：双 sink 日志（console + file），支持 `text` / `json` 格式；`-init` 生成示例配置；启动横幅打印版本、加载的配置文件与逐字段来源

#### 修复与重构

- `refactor(config)`：抽象配置层为统一 CLI/ENV/YAML Source + 集中校验
- `fix(goreleaser)`：移除 ldflags 的 `-trimpath`，修复 `archives` deprecation
- `fix(ci)`：`workflow_call` outputs 改用 block 风格，避免花括号冲突
- `fix(push)`：授予 `contents:write`，使 reusable CI 能推送 `build-counter` 分支

#### 发布基础设施

- 版本体系 + GitHub Actions：`version` 包（ldflags 注入构建信息）+ 全局 Build Number + GoReleaser 驱动的 push/release workflow

#### 下载

Linux 与 Windows，amd64 与 arm64 — 见 [Releases](https://github.com/MartinZiYun/ProxyDge/releases) 页面。
