## English

### ProxyDge v0.5.0 — cross-platform service management

Minor release adding system service support via `github.com/kardianos/service`. ProxyDge can now run as a Windows Service, Linux systemd unit, or macOS launchd daemon with install, uninstall, and lifecycle control from the CLI.

#### New features

- **`proxydge service` subcommands**:
  - `install [-config <path>]` — install as a system service and auto-start. Config path defaults to `<exe-dir>/config.yaml`; override with `-config`. Path is converted to absolute automatically. If already installed, prints a notice and exits without restarting or overwriting.
  - `uninstall` — remove the system service.
  - `start` — start the installed service.
  - `stop` — stop the running service.
  - `status` — print service status (Running / Stopped / Unknown).
  - All subcommands accept `-lang <locale>` to override the display language.

- **Service lifecycle via `service.Interface`**: when running under a service manager (detected via `service.Interactive()`), `cmdStart` delegates to `proxydgeService` which implements `service.Interface`. `Start()` launches the gateway asynchronously; `Stop()` closes the listener and waits for shutdown. Fatal gateway errors trigger `os.Exit(1)` to activate the OS recovery mechanism (Windows `OnFailure: restart`, systemd `Restart: always`).

- **Idempotent install**: checking service status before installing — if already installed (any state), prints `service.already_installed` and exits 0. No restart, no config overwrite.

- **Config path safety**: install converts the config path to absolute via `filepath.Abs()` and verifies the file exists before proceeding. Prevents service startup failures from relative paths or missing files.

#### Architecture

- **`gateway_runner.go`**: extracted `runGateway(cfg *config.Config) (closer, <-chan error, err)` from `cmdStart`. Shared by the interactive path and the service path. `buildLogger`, `parseLevel`, and `multiHandler` moved here.
- **`service_ctrl.go`**: `ServiceController` interface with `kardianosServiceController` production implementation and `newServiceControllerFunc` factory variable for test injection. `cmdService` dispatches subcommands.
- **`service_program.go`**: `proxydgeService` (service.Interface) with single-consumer errc model — monitor goroutine is the sole reader, `Stop()` waits via `done` channel.
- **`service_ctrl_test.go`**: 14 tests using `fakeServiceController` — covers dispatch, install (missing config, already installed, fresh), control (start/stop/uninstall success, not-installed, generic error), and status (running/stopped/unknown/error).

#### i18n

- 12 new translation keys across en, zh-CN, zh-TW covering all service operations and error messages.
- `service.not_installed` used when start/stop/uninstall encounter `service.ErrNotInstalled`.

#### Dependencies

- `github.com/kardianos/service v1.3.0` — cross-platform service management (Windows, Linux/systemd, macOS/launchd).
- `golang.org/x/sys v0.34.0` (transitive).

**Full Changelog**: https://github.com/MartinZiYun/ProxyDge/compare/v0.4.1...v0.5.0

## 简体中文

### ProxyDge v0.5.0 — 跨平台系统服务管理

次版本：通过 `github.com/kardianos/service` 添加系统服务支持。ProxyDge 现可作为 Windows Service、Linux systemd 单元或 macOS launchd 守护进程运行，支持从 CLI 安装、卸载和生命周期控制。

#### 新功能

- **`proxydge service` 子命令**：
  - `install [-config <path>]` — 安装为系统服务并自动启动。配置路径默认 `<exe-dir>/config.yaml`，可通过 `-config` 覆盖。路径自动转为绝对路径。已安装时打印提示，不重启不覆盖。
  - `uninstall` — 卸载系统服务。
  - `start` — 启动已安装的服务。
  - `stop` — 停止运行中的服务。
  - `status` — 显示服务状态（运行中 / 已停止 / 未知）。
  - 所有子命令支持 `-lang <locale>` 覆盖显示语言。

- **基于 `service.Interface` 的服务生命周期**：检测到服务管理器环境时（`service.Interactive()`），`cmdStart` 委托给实现 `service.Interface` 的 `proxydgeService`。`Start()` 异步启动网关；`Stop()` 关闭 listener 并等待关闭。致命网关错误触发 `os.Exit(1)` 以激活 OS 恢复机制（Windows `OnFailure: restart`、systemd `Restart: always`）。

- **幂等安装**：安装前查询服务状态——已安装（任意状态）时打印 `service.already_installed` 并以 exit 0 退出。不重启、不覆盖配置。

- **配置路径安全**：install 通过 `filepath.Abs()` 将配置路径转为绝对路径，并在继续前校验文件存在性。防止相对路径或文件缺失导致的服务启动失败。

#### 架构

- **`gateway_runner.go`**：从 `cmdStart` 提取 `runGateway(cfg *config.Config) (closer, <-chan error, err)`，供交互路径和服务路径共用。`buildLogger`、`parseLevel`、`multiHandler` 移入此文件。
- **`service_ctrl.go`**：`ServiceController` 接口 + `kardianosServiceController` 生产实现 + `newServiceControllerFunc` 工厂变量（测试注入）。`cmdService` 分发子命令。
- **`service_program.go`**：`proxydgeService`（service.Interface），单消费者 errc 模型——monitor goroutine 唯一读取，`Stop()` 通过 `done` channel 等待。
- **`service_ctrl_test.go`**：14 个测试，使用 `fakeServiceController`——覆盖分发、install（缺配置、已安装、全新）、control（start/stop/uninstall 成功、未安装、通用错误）、status（运行/停止/未知/错误）。

#### 国际化

- 12 个新翻译键，覆盖 en、zh-CN、zh-TW 三语言，涵盖所有服务操作和错误消息。
- start/stop/uninstall 遇到 `service.ErrNotInstalled` 时使用 `service.not_installed` 键。

#### 依赖

- `github.com/kardianos/service v1.3.0` — 跨平台服务管理（Windows、Linux/systemd、macOS/launchd）。
- `golang.org/x/sys v0.34.0`（传递依赖）。

**完整变更**：https://github.com/MartinZiYun/ProxyDge/compare/v0.4.1...v0.5.0
