## English

### ProxyDge v0.4.0 — configurable TCP normalization target & address-family mismatch policy

Minor release adding two TCP configuration fields and one config-format migration.

#### What's new

- **`tcp.header-version` (`v1` | `v2`, default `v2`)**: choose which PROXY Protocol version the gateway normalizes connections to before forwarding downstream. `v2` (binary, previous always-on behavior) or `v1` (text `PROXY TCP4/TCP6 ...` lines) for downstream services that only understand the legacy text format. Exposed as YAML key, `PROXYDGE_TCP_HEADER_VERSION`, and `-tcp-header-version`. UDP output is unchanged.

- **`tcp.family-mismatch` (`reject` | `unknown` | `legacy`, default `reject`)**: controls what happens when an upstream sends a header whose declared address family contradicts its addresses — the wire-craftable shape being AF_INET6 carrying a `::ffff:`-mapped IPv4 destination. Previous releases silently re-encoded such headers, letting downstream receive e.g. `::ffff:192.168.1.1` labeled as IPv6, which strict consumers can misparse or misroute.
  - `reject`: close the connection before dialing downstream (log the rejection)
  - `unknown`: forward the protocol's honest no-address form (`PROXY UNKNOWN` / LOCAL+AF_UNSPEC) so downstream falls back per spec
  - `legacy`: keep the historical byte-for-byte behavior; selecting this prints a startup WARNING

  Direct connections and stripped untrusted headers are rebuilt from real socket addresses and are never affected.

- **Config format 2 → 3**: old configs auto-migrate on first start. The migrated file gets `tcp.family-mismatch: "legacy"` written EXPLICITLY when the key is absent, so upgrading does not change wire behavior until you deliberately switch to `reject`/`unknown`; fresh configs and `proxydge init` default to `reject`. The same migration back-fills `tcp.idle-timeout` (introduced in v0.3.2 without a version bump, so older version-2 files never gained the line). A `.bak` backup is written before any change, as always.

#### Upgrade checklist

1. Start once — the config migrates automatically (check the `NOTICE` line).
2. If you rely on the historical mapping behavior, nothing changes (`legacy` was injected). Otherwise set `tcp.family-mismatch: reject` (strictest) or `unknown`.
3. If your downstream only understands PROXY v1, set `tcp.header-version: v1`.

## 简体中文

### ProxyDge v0.4.0 — 可配置的 TCP 归一目标版本与地址族不一致处置

次版本：新增两个 TCP 配置字段与一次配置格式迁移。

#### 新功能

- **`tcp.header-version`（`v1` | `v2`，默认 `v2`）**：选择网关把连接归一为哪个 PROXY Protocol 版本再转发下游。`v2`（二进制，即此前唯一行为）或 `v1`（文本 `PROXY TCP4/TCP6 ...` 行），供只认旧文本格式的下游服务使用。三路暴露：YAML、`PROXYDGE_TCP_HEADER_VERSION`、`-tcp-header-version`。UDP 输出不变。

- **`tcp.family-mismatch`（`reject` | `unknown` | `legacy`，默认 `reject`）**：处置上游发来的"声明地址族与实际地址矛盾"的 header——线上可构造的唯一形态是 AF_INET6 装着 `::ffff:` 映射形式的 IPv4 目的地址。此前版本会静默重编码，下游可能收到标记为 IPv6 的 `::ffff:192.168.1.1`，严格的解析器可能解析异常或误连。
  - `reject`：拨号下游之前关闭连接并记日志
  - `unknown`：转发协议规定的无地址形式（`PROXY UNKNOWN` / LOCAL+AF_UNSPEC），按协议告知下游走兜底逻辑
  - `legacy`：逐字节保持历史行为；选择后启动时打印 WARNING

  直连与被 strip 的不可信头由真实套接字地址重建，天然自洽，永不误伤。

- **配置格式 2 → 3**：旧配置首次启动自动迁移。源文件缺失 `tcp.family-mismatch` 时会**显式写入 `"legacy"`**——升级不改变线上行为，直到你主动切换 `reject`/`unknown`；全新配置和 `proxydge init` 默认 `reject`。同一次迁移顺带补全 `tcp.idle-timeout`（v0.3.2 引入时未升配置版本，旧 version-2 文件一直没有这一行）。迁移前照常先写 `.bak` 备份。

#### 升级步骤

1. 启动一次——配置自动迁移（留意 `NOTICE` 行）。
2. 若依赖历史映射行为则无需动作（已注入 `legacy`）；否则设置 `tcp.family-mismatch: reject`（最严格）或 `unknown`。
3. 若下游只认 PROXY v1，设置 `tcp.header-version: v1`。
