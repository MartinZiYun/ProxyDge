## English

### ProxyDge v0.5.1 — Go 1.27 toolchain upgrade

Patch release with no application code changes. Release binaries are now built with Go 1.27.3 (previously 1.26.6), which carries the upstream `crypto/x509` fix for a certificate chain handling flaw (CVE-2026-111943) that could let an attacker with an untrusted intermediate CA certificate bypass TLS verification in Go's standard library.

ProxyDge itself does no outbound TLS or HTTPS certificate validation — it is a listener-only PROXY protocol gateway — so that path is not directly reachable from this codebase. The rebuild keeps released binaries on a patched, supported toolchain and picks up the runtime and standard library fixes shipped between 1.26.6 and 1.27.3.

#### Changes

- **Build toolchain**: Go 1.26.6 → Go 1.27.3 (`go` directive in `go.mod`).
- **READMEs**: Go badge updated to 1.27+.
- No changes to gateway behavior, configuration format, CLI flags, or i18n strings. `go.sum` is unchanged — no dependency upgrades.

#### Upgrade notes

Drop-in replacement for v0.5.0; no config migration needed. Prebuilt binaries stay CGO-free static builds for all published GOOS/GOARCH targets.

**Full Changelog**: https://github.com/MartinZiYun/ProxyDge/compare/v0.5.0...v0.5.1

## 简体中文

### ProxyDge v0.5.1 — Go 1.27 工具链升级

补丁版本，无应用代码改动。发布二进制改用 Go 1.27.3 构建（原 1.26.6），包含上游 `crypto/x509` 证书链处理缺陷（CVE-2026-111943）的修复——该缺陷可能使持有不受信中间 CA 证书的攻击者绕过 Go 标准库的 TLS 校验。

ProxyDge 本身不发起对外 TLS/HTTPS 请求，也不做证书校验（它是只监听入站的 PROXY protocol 网关），因此这条攻击路径在本项目中不可直接触达。重新构建的目的在于让发布产物停留在已修补、仍在支持的编译器版本上，并顺带获得 1.26.6 至 1.27.3 之间的运行时与标准库修复。

#### 变更

- **构建工具链**：Go 1.26.6 → Go 1.27.3（`go.mod` 的 `go` 指令）。
- **README**：Go 徽章更新为 1.27+。
- 网关行为、配置格式、CLI 参数、多语言文案均无改动。`go.sum` 未变——没有依赖升级。

#### 升级说明

可直接替换 v0.5.0，无需迁移配置。所有发布平台仍为 CGO-free 静态二进制。

**完整变更**：https://github.com/MartinZiYun/ProxyDge/compare/v0.5.0...v0.5.1
