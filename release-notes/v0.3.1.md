## English

### ProxyDge v0.3.1 — Pipe idle timeout, config fixes & gateway hardening

Patch release with a new TCP pipe idle timeout (DoS prevention), config migration fixes, transient error tolerance, UDP session race fix, and a config field registry with consistency testing.

> **Upgrading from v0.3.0?** Three things to know:
> 1. If your config was auto-migrated, v1 flat field values may have been lost — re-migrate from your `.bak` backup.
> 2. **New default**: `tcp.idle-timeout` defaults to 5m. Connections idle for 5 minutes in either direction are now closed. Set `tcp.idle-timeout: "0"` to restore the old no-timeout behavior.
> 3. `detect-timeout: 0` is now valid (blocks indefinitely waiting for a complete header).

#### New features

- **TCP pipe idle timeout** (`tcp.idle-timeout`): after header detection, each pipe direction gets an independent idle timer. If no data flows in a direction for the configured duration, that side is closed. Default 5m; set `0` to disable. Each direction is independent — activity in one direction does NOT extend the other's deadline. Prevents unauthenticated clients from holding goroutines + fds indefinitely (DoS vector when combined with fd exhaustion).
- **Config field registry**: `configFields` is now the single source of truth for field names, sections, defaults, and display order. `Describe()` output groups fields by section (`[General]`, `[Trust]`, `[TCP]`, `[UDP]`, `[Logging]`) with v2 nested names (`tcp.detect-timeout`, `udp.idle-timeout`). A consistency test (`TestFieldRegistryConsistency`) verifies the full chain: registry → Config → sampleConfig → generateMigratedConfig → knownConfigKeys → defaultsSource. Adding a field without registering it everywhere causes CI to fail.

#### Fixes

- **`detect-timeout: 0` now valid**: `New()` documentation said "Pass 0 to block indefinitely" but `Validate()` rejected it. Now `0` passes validation — the gateway blocks indefinitely waiting for a complete PROXY header. UDP is unaffected (detect-timeout is TCP-only).
- **Bare IP in `trusted-networks`**: config validation rejected bare IPs like `10.0.0.1` with "invalid CIDR address". The trust checker already supported bare IPs, but the config validation layer used `net.ParseCIDR` only. Now both layers accept CIDR and bare IP.
- **v1→v2 config migration**: three bugs in `generateMigratedConfig`:
  1. **V1 flat fields not mapped**: flat fields (`detect-timeout`, `idle-timeout`, `max-sessions`, `max-datagram-size`, `udp-output`) were treated as unknown fields and preserved verbatim at the bottom of the migrated file, while the corresponding v2 nested fields got default values. Now they are mapped to their v2 locations.
  2. **In-memory values lost**: after migration wrote the v2 file, the in-memory `Config` still reflected the old v1 parse. Now the file is re-read after migration so in-memory values match the migrated file.
  3. **Migration output didn't match `-init` template**: field order, section headers, and comments diverged from `proxydge -init` output. Now the migrated file mirrors the template structure.
- **Transient accept/read error tolerance** (Bug 2): `Accept()` (TCP) and `ReadFromUDP()` (UDP) returning EMFILE/ENFILE/EINTR/timeout no longer terminate the gateway. A short backoff (5ms) retries the call. Prevents fd-exhaustion DoS from killing the process.
- **UDP session race** (Bug 1): `Create()` returning an expired session (stale map entry during `expire()` window) now drops the datagram instead of using the dead session. `refresh()` no longer re-arms a dead timer via `Reset()`.
- **`log.file.format` default**: `sampleConfig` and `generateMigratedConfig` said "json" but the actual default was "text". Fixed to match.
- **i18n help text**: added `-tcp-idle-timeout` flag; updated `-tcp-detect-timeout` description to mention `0=block indefinitely`; fixed `-log-file-format` default from "json" to "text". All three locales (en, zh-CN, zh-TW) updated.

#### What changed

- `internal/config/config.go`: `Validate()` accepts `detect-timeout: 0` and `tcp.idle-timeout`; new `TCPIdleTimeout` field, registry entry, env/flag sources; `generateMigratedConfig` maps v1 flat fields + matches template; `fileSource.Apply` re-reads after migration; `configFields` enriched with `section`/`defVal`/`comment`.
- `internal/gateway/gateway.go`: `New()` takes `pipeIdleTimeout`; `Serve()` retries transient errors via `IsTemporaryNetError`.
- `internal/gateway/pipe.go`: `deadlineReader` wraps each direction independently; `pipeStream` takes `idleTimeout` parameter.
- `internal/udp/gateway.go`: `handleDatagram` drops datagrams when `Create` returns an expired session; `Serve()` retries transient read errors.
- `internal/udp/session.go`: `refresh()` checks `done` before `Reset`.
- `internal/i18n/locales/*.yaml`: help text updated with new flags and corrected defaults.
- `README.md`, `README.zh-CN.md`: sample config + flags table updated.
- `internal/config/registry_test.go`: new `TestFieldRegistryConsistency` — 5-point chain verification.

## 简体中文

### ProxyDge v0.3.1 — 管道空闲超时、配置修复与网关加固

补丁版本：新增 TCP 管道空闲超时（防 DoS）、配置迁移修复、临时错误容忍、UDP 会话竞态修复、配置字段注册表与一致性测试。

> **从 v0.3.0 升级？** 需要知道三件事：
> 1. 如果配置被自动迁移过，v1 扁平字段值可能已丢失 — 请从 `.bak` 备份重新迁移。
> 2. **新默认值**：`tcp.idle-timeout` 默认 5 分钟。任一方向空闲 5 分钟的连接将被关闭。设 `tcp.idle-timeout: "0"` 可恢复旧的无超时行为。
> 3. `detect-timeout: 0` 现在合法（无限等待完整 header）。

#### 新功能

- **TCP 管道空闲超时**（`tcp.idle-timeout`）：header 探测后，管道每个方向独立计时。某方向无数据流动超过配置时长则关闭该侧。默认 5m；设 `0` 禁用。每方向独立 — 一个方向的流量不会延长另一个方向的 deadline。防止未认证客户端永久占用 goroutine + fd（叠加 fd 耗尽时构成 DoS）。
- **配置字段注册表**：`configFields` 现为字段名、区块、默认值、显示顺序的唯一数据源。`Describe()` 输出按区块分组（`[General]`、`[Trust]`、`[TCP]`、`[UDP]`、`[Logging]`），使用 v2 嵌套命名（`tcp.detect-timeout`、`udp.idle-timeout`）。一致性测试（`TestFieldRegistryConsistency`）验证完整链：注册表 → Config → sampleConfig → generateMigratedConfig → knownConfigKeys → defaultsSource。新增字段漏改任何一处 → CI 直接失败。

#### 修复

- **`detect-timeout: 0` 现合法**：`New()` 文档写着 "Pass 0 to block indefinitely" 但 `Validate()` 拒绝。现在 `0` 通过校验 — 网关无限等待完整 PROXY header。UDP 不受影响（detect-timeout 是 TCP 专用）。
- **`trusted-networks` 裸 IP**：配置校验拒绝裸 IP（如 `10.0.0.1`）。信任检查器本已支持，但配置校验层只用了 `net.ParseCIDR`。现两层均接受 CIDR 和裸 IP。
- **v1→v2 配置迁移**：`generateMigratedConfig` 三个 bug：
  1. **v1 扁平字段未映射**：扁平字段被当作未知字段留在迁移文件底部，v2 嵌套字段用默认值。现已映射到 v2 位置。
  2. **内存值丢失**：迁移写入 v2 文件后，内存 `Config` 仍反映旧 v1 解析。现迁移后重读文件。
  3. **迁移输出不匹配 `-init` 模板**：字段顺序、区块头和注释与模板不一致。现已对齐。
- **临时 Accept/Read 错误容忍**（Bug 2）：`Accept()`（TCP）和 `ReadFromUDP()`（UDP）返回 EMFILE/ENFILE/EINTR/超时不再终止网关。短退避（5ms）后重试。防止 fd 耗尽 DoS 杀死进程。
- **UDP 会话竞态**（Bug 1）：`Create()` 返回已过期会话（`expire()` 窗口内 map 残留）时丢弃数据报，不再使用死会话。`refresh()` 不再通过 `Reset()` 重武装死定时器。
- **`log.file.format` 默认值**：`sampleConfig` 和 `generateMigratedConfig` 写 "json" 但实际默认是 "text"。已修正。
- **i18n 帮助文本**：新增 `-tcp-idle-timeout` flag；`-tcp-detect-timeout` 描述补充 `0=无限等待`；`-log-file-format` 默认值从 "json" 改为 "text"。三个语言（en、zh-CN、zh-TW）均已更新。

#### 变更内容

- `internal/config/config.go`：`Validate()` 放行 `detect-timeout: 0` 和 `tcp.idle-timeout`；新增 `TCPIdleTimeout` 字段、注册表条目、env/flag 源；`generateMigratedConfig` 映射 v1 扁平字段 + 匹配模板；`fileSource.Apply` 迁移后重读；`configFields` 富化为注册表。
- `internal/gateway/gateway.go`：`New()` 接受 `pipeIdleTimeout`；`Serve()` 通过 `IsTemporaryNetError` 重试临时错误。
- `internal/gateway/pipe.go`：`deadlineReader` 每方向独立计时；`pipeStream` 接受 `idleTimeout` 参数。
- `internal/udp/gateway.go`：`handleDatagram` 在 `Create` 返回过期会话时丢弃数据报；`Serve()` 重试临时读错误。
- `internal/udp/session.go`：`refresh()` 在 `Reset` 前检查 `done`。
- `internal/i18n/locales/*.yaml`：帮助文本更新新 flag 和修正默认值。
- `README.md`、`README.zh-CN.md`：示例配置 + flag 表更新。
- `internal/config/registry_test.go`：新增 `TestFieldRegistryConsistency` — 5 点链验证。
