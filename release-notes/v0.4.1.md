## English

### ProxyDge v0.4.1 — UDP datagram fix, connection limit & test hardening

Patch release fixing a UDP datagram-drop bug on wildcard listeners, adding a TCP concurrent connection limit, and expanding test coverage across gateway, config, and proxyproto packages.

#### Fixes

- **UDP direct datagram drop on wildcard listeners**: when listening on `:0.0.0.0` or `:[port]` (wildcard), direct datagrams (no PROXY header) from trusted sources were silently dropped. The gateway failed to match the sender's address against the connected upstream socket because the wildcard listener lacked a specific local address. Fixed by using the actual peer address from `ReadFromUDP` for session routing. `go-proxyproto` upgraded to v0.15.0 as part of this fix.
- **`tcp.max-connections` flag/env not applied**: the `-tcp-max-connections` CLI flag and `PROXYDGE_TCP_MAX_CONNECTIONS` env var were parsed but never applied to the config — the `flagSource.Apply` and `envSource.Addrs` branches were missing. Fixed with propagation guard tests.
- **Config field propagation guards**: three fields (`tcp.max-connections`, `tcp.header-version`, `tcp.family-mismatch`) lacked `mark()` calls in some sources, causing `Describe()` to report "default" even when set via flag/env/file. Fixed and guarded by `TestConfigPropagation`.

#### New features

- **`tcp.max-connections`** (default 4096, `0`=unlimited): caps concurrent TCP connections. When the limit is reached, new connections are accepted then immediately closed. Prevents fd and goroutine exhaustion under connection floods.
- **`udp.max-sessions` accepts `0`=unlimited**: aligns with `tcp.max-connections` validation symmetry.

#### Testing

- **proxyproto UDP coverage**: 61.3% → 74.2% — branch coverage for UDP datagram reader/writer and type mismatch paths.
- **main package mapping functions**: 5 pure functions (`gatewayPolicy`, `untrustedProxyAction`, `tcpHeaderVersion`, `familyMismatch`, `udpHeaderMode`) from 0% → 100%.
- **Benchmark expansion**: idle-enabled paths, v1↔v2 serialization, large-datagram UDP, session churn scenarios.
- **Debug logging**: UDP `readLoop` `WriteToUDP` error logging for diagnosing client Pong delivery.

#### Other

- CI workflow renamed from `push` to `dev-build` for clarity.

**Full Changelog**: https://github.com/MartinZiYun/ProxyDge/compare/v0.4.0...v0.4.1

## 简体中文

### ProxyDge v0.4.1 — UDP 数据报修复、连接上限与测试加固

补丁版本：修复通配监听器上 UDP 数据报丢弃 bug，新增 TCP 并发连接上限，扩充 gateway、config、proxyproto 包的测试覆盖。

#### 修复

- **通配监听器上 UDP 直连数据报丢弃**：监听 `0.0.0.0` 或 `:[port]`（通配）时，可信来源的直连数据报（无 PROXY header）被静默丢弃。通配监听器缺少具体本地地址，导致无法匹配发送方地址到已连接的上游 socket。修复后使用 `ReadFromUDP` 返回的实际对端地址做会话路由。`go-proxyproto` 升级至 v0.15.0。
- **`tcp.max-connections` flag/env 未生效**：`-tcp-max-connections` CLI flag 和 `PROXYDGE_TCP_MAX_CONNECTIONS` 环境变量被解析但从未应用到配置——`flagSource.Apply` 和 `envSource.Addrs` 分支缺失。已修复并添加传播守卫测试。
- **配置字段传播守卫**：三个字段（`tcp.max-connections`、`tcp.header-version`、`tcp.family-mismatch`）在部分 source 中缺少 `mark()` 调用，导致 `Describe()` 即使通过 flag/env/file 设置也报告 "default"。已修复并用 `TestConfigPropagation` 守卫。

#### 新功能

- **`tcp.max-connections`**（默认 4096，`0`=不限制）：限制 TCP 并发连接数。达到上限时新连接被 accept 后立即关闭，防止连接洪水耗尽 fd 和 goroutine。
- **`udp.max-sessions` 支持 `0`=不限制**：与 `tcp.max-connections` 校验对称。

#### 测试

- **proxyproto UDP 覆盖率**：61.3% → 74.2% — UDP 数据报读写器及类型不匹配路径的分支覆盖。
- **main 包映射函数**：5 个纯函数（`gatewayPolicy`、`untrustedProxyAction`、`tcpHeaderVersion`、`familyMismatch`、`udpHeaderMode`）从 0% → 100%。
- **基准测试扩充**：idle 启用路径、v1↔v2 序列化、大报文 UDP、会话 churn 场景。
- **调试日志**：UDP `readLoop` `WriteToUDP` 错误日志，用于诊断客户端 Pong 送达。

#### 其他

- CI 工作流从 `push` 重命名为 `dev-build` 以提高清晰度。
